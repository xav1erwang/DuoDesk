# 开机服务与发现恢复

Mac 应用默认配置开机服务，不再提供「登录时启动」或「开机后允许连接」开关。macOS 管理管理员授权和后台项目审批；需要授权或设置失败时，应用「设置 → 权限」才显示完成授权或重试的入口。应用需安装在固定位置，并使用稳定的 Apple 开发或分发签名；临时签名构建不注册此服务。

录屏与辅助功能许可仍由 macOS 决定。FileVault 的启动磁盘解锁发生在普通 macOS 服务运行前，本功能不能代替该解锁。开机服务也不能使已关机的电脑自行开机；休眠唤醒仍取决于硬件、电源、网卡及网络睡眠代理。

## 实现

| 进程 | 启动方式 | 职责 |
| --- | --- | --- |
| 开机守护进程 | `SMAppService.daemon`，`com.duodesk.host.boot` | 验证本机 XPC 调用者、保存已有 Mac 身份与配对名单、安装受保护的登录窗口主机 |
| 登录窗口主机 | 全局 `LoginWindow` LaunchAgent | 在登录前提供必须配对的局域网桌面与输入，登录后退出 |
| 用户主机 | `SMAppService.agent`，`Aqua` 会话 | 登录后以用户身份运行正常应用，异常退出后由系统重新启动 |

登录窗口主机使用 `/Library/Application Support/DUO你电脑/LoginHost.app`。守护进程复制后检查签名，拒绝符号链接；目录只允许 root 访问。保护身份文件为 root 所有、0600，不写入日志或仓库。XPC 双向限制为同 Team、同 `com.duodesk.host` 标识的 Apple 签名代码，写操作只属于启用时的控制台用户。

登录前后保留相同 TLS 身份和识别密钥；手机继续校验原来的 Mac 身份。登录窗口不允许新配对、剪贴板、应用启动、窗口控制、Touch Bar 或虚拟显示器，只接受桌面、输入、视口及必要的连接消息。采集使用已有物理屏，不改原生分辨率或刷新率。配对名单变更会结束旧登录窗口会话并重新载入；持续 XPC 连接中断时也停止提供服务。

后台待机默认允许自动休眠，登录窗口主机也不持有防空闲休眠请求。用户明确开启「空闲时保持唤醒」才会在普通主机空闲时阻止自动休眠；手动休眠仍由系统处理。网络唤醒在用户希望连接时尝试，不为此修改系统电源设置。

macOS 后台项目可停用守护进程；停用后，登录窗口主机也会失去连接并退出。普通用户的钥匙串身份和配对资料保留。

## 发现恢复

Mac 监听网络恢复及系统、屏幕唤醒事件，在 2 秒后重新发布 Bonjour，10 秒后再补一次。刷新先撤下旧服务，等待现有的 1.5 秒间隔后重新注册，已有串流连接保持。监听器已失败时重建监听器。

手机扫描未发现某台已配对 Mac 时，按保存的服务名主动进行组播 TXT 查询。只有识别标签匹配已保存密钥才恢复本地条目，随后连接仍需通过原有 TLS 固定身份校验。无效或旧标签不会被当作有效结果，查询最多等待 6 秒。列表左上角的「重新搜索」重建浏览器，并在新结果稳定前保留当前条目。

## 验证记录（2026-11-07）

- Mac、iOS 模拟器和手机构建通过；开机身份连续性、无效配对拒绝、只读身份存储以及 256 个消息值的白名单检查通过。
- 已配对 Mac 的漏扫恢复集成检查通过，包括隐藏正常浏览结果后恢复连接、错误识别密钥拒绝、固定身份拒绝及地址回退。
- 实体 Duo 曾仅列出 Air；重新启动浏览后日志同时列出 Pro 和 Air。用户确认进入 Pro 桌面，主机记录实际采集、编码、发送及输入。该证据确认恢复连接，尚不能确定间歇性漏扫的全部原因。
- 深色组合、键盘与触控板已在 Duo 模拟器渲染；字符发光只用于键面文字，按压反馈和修饰键状态继续保留。
- 已获用户授权启用服务：设置显示「已启用」，系统确认 root 守护进程运行、Aqua 代理已注册，登录窗口代理安装成功。系统目录为 root:wheel、0700，普通用户无法读取其中身份文件。首次注册出现过审批状态延迟，现会在系统完成授权后自动继续配置。
- 已将正式主机切换为系统托管启动，并在空闲状态发送终止信号检查恢复；系统自动重启主机，日志仍显示一台已配对设备、TLS 监听和发现注册。未获信任的本地验证程序被 XPC 拒绝。
- 一项额外的可信调用验证未通过：临时 `boot-xpc-positive` 程序因 AMFI 报告签名无效（-420）被 macOS 拦截并移至废纸篓。保留了系统拦截，未绕过或重试，该项不计为通过。随后正式应用严格验签通过，服务与主机仍正常运行；诊断记录保存在忽略的 `Temp/`。
- 真实登录窗口的 ScreenCaptureKit/TCC 行为、登录交接和休眠唤醒仍需实机验收。未自动注销或重启用户电脑。

## 参考与许可

研究了 [RustDesk 的 macOS 平台代码](https://github.com/rustdesk/rustdesk/blob/3513c9751db598567b2d1ac7e0637f8ecc5a5fc0/src/platform/macos.rs) 和启动配置，采用守护进程与会话代理分工的思路。实现独立编写，未复制其 GPL 代码；DuoDesk 与 Sill 的 Apache-2.0 许可和归属保持。RustDesk 的采集路径与本项目的 ScreenCaptureKit 不同，服务架构相似不能证明登录窗口画面或流畅度相同。

Apple 官方依据：[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)、[更新旧版 helper 的服务注册方式](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos)、[Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)。本次使用 Xcode 27.2 / Swift 6.4.2 构建，沿用项目既有部署目标。
